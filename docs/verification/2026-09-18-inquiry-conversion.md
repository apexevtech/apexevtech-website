# 询盘转化优化 — 2026-09-18

## 流程

- 全部产品和联系页表单增加直接WhatsApp及邮件入口，预填型号/页面用途，不包含客户填写内容。
- Company、Country标明选填；消息增加格式示例；姓名最短长度及输入上限与后端校验一致。
- 请求过程中锁定重复提交并禁用编辑，保留失败内容；服务端字段错误后定位第一个错误字段，隐私勾选框增加错误关联；失败继续提供邮件入口。
- 下载按钮标明Word规格文件，保留正常下载URL与现有catalog_download统计。
- 手机端WhatsApp悬浮入口缩小为带无障碍标签的图标，点击区域至少44px；填写表单时隐藏悬浮入口，表单内直接联系方式继续可用。桌面保留文字入口。绿色加深提高白色文字对比。
- 联系页邮箱、电话改为带统计的入口。

## 衡量

| 事件 | 含义 |
| --- | --- |
| inquiry_start | 本轮开始填写，首次更改触发一次 |
| inquiry_submit | 表单通过浏览器校验并尝试发出请求 |
| inquiry_error | 浏览器校验、服务端错误代码或网络失败，不发送填写值或错误原文 |
| generate_lead | 服务器确认询盘送达成功 |
| whatsapp_click / email_click / phone_click | 联系入口点击，不代表实际对话或有效销售线索 |
| catalog_download | 产品资料点击，不代表文件保存完成；不与自动file_download相加 |

这些事件遵循现有统计同意机制。新增page_path仅为路径，不包含查询参数；本次事件参数没有姓名、邮箱、消息或完整表单值。跟踪异常不会打断联系或提交动作。既有GA4 generate_lead关键事件设置保留，没有新建其他关键事件。

后端此前对反垃圾过滤返回通用成功，客户端可能误记线索。成功响应新增leadRecorded：仅邮件送达成功true，过滤提交false；客户端只有true时记录generate_lead。此信号说明系统送达成功，不证明客户合格或产生订单。
